# Группы компьютеров и подгруппы

Обязательное уточнение владельца после выбора макета A. В интерфейсе макета
используются названия «Группы компьютеров», «Умная группа» (динамическая)
и «Ручная группа» (статическая). «Коллекция» — технический синоним.
В HTML A работают дерево, папки/подгруппы, создание, изменение, перенос и preview.
В HTML все изменения только в памяти. В M1.1 появились отдельные Rust-engine,
локальное SQLite-хранение и CLI preview. M1 дополнен нативной egui-консолью и редактором;
сервер/API ещё не реализованы. Сценарии: [m1-console.md](m1-console.md).
Подробности: [m1-core.md](m1-core.md).

Имена выше — примеры пользовательских коллекций, не фиксированный каталог.
Самостоятельное создание/редактирование обязательно; не заменить его несколькими
зашитыми переключателями. Сохранить спокойный стиль A и текущий знак Orkestr.

## Папки и вложенность

- Папки содержат другие папки, умные и ручные группы. Родитель выбирается при
  создании/редактировании; в выбранной папке есть «Создать подгруппу».
- Перенос — смена родителя. Нельзя поместить папку в себя или своего потомка.
- Папку с детьми нельзя удалить/превратить в выборку до переноса её детей.
- Состав папки — объединение компьютеров её потомков без дубликатов. Это не сумма
  счётчиков: RAM >=8 и >=16 пересекаются.
- Папка организует дерево, не задаёт скрытый фильтр детям. Правила каждой группы
  явные и независимые. Наследование фильтров не включать неявно.
- Путь `Приложения / Chrome / Последняя версия` виден в рабочей области и поиске.

Выбор коллекции показывает **какие ПК входят**, **сколько их** и **что установлено**.
Для software-фильтра добавить колонки: приложение, установленная версия,
эталон из библиотеки, результат сравнения, дата скана. Для hardware — RAM и другие
выбранные поля. Карточка ПК по-прежнему доступна из строки.

## Статическая

- Список вручную выбранных DeviceId, например тестовые ПК перед обновлением.
- Добавление/удаление участников из таблицы и редактора.
- Изменение RAM/ПО само не меняет состав.
- Удаление коллекции не удаляет компьютеры и их инвентаризацию.
- Предпросмотр состава и количества до сохранения, сохранение на сервере для всех консолей.

## Динамическая

- Сохранённое выражение, автоматически вычисляемое по последним доступным данным.
- Типизированные поля: оборудование, ОС, домен/OU, источник, площадка,
  установленное ПО/издатель/версия, время и полнота скана.
- Операторы для чисел: =, !=, >, >=, <, <=; для текста — соответствующие текстовые.
- Группы И/ИЛИ позволяют объединять условия и диапазоны. Условия одной установки
  приложения должны совпасть на одной записи ПО, а не на разных продуктах одного ПК.
- Редактор показывает живой **preview числа и списка совпадений** до сохранения;
  результат вычисляется сервером, не запускает сканирование/установку автоматически.
- После нового скана или изменения эталона библиотеки состав пересчитывается;
  UI показывает время/версию данных, чтобы счётчик и список соответствовали одному снимку.

## Chrome и последняя версия из библиотеки

Приложение выбирать по записи библиотеки, не по одной строке DisplayName contains.
Пример условий:

```text
Приложение = Google Chrome
Канал = Stable
Установленная версия = Последняя известная версия в библиотеке
```

Вторая коллекция отличается последним условием:

```text
Установленная версия < Последняя известная версия в библиотеке
```

Эталон — **ссылка на библиотеку**, не скопированный в фильтр номер. Когда в библиотеке
появится новая корректно распознанная версия, ПК переместятся между выборками по своим
данным, без ручной правки каждого условия. Учитывать канал, архитектуру и схему сравнения
версий; `2.10` новее `2.9`. Не сравнивать версии как простые строки.

Название эталона в UI — «Последняя известная в библиотеке», с номером и временем
проверки. Это не обещание знания абсолютной последней версии в Интернете.
Предусмотреть отдельный эталон «Последняя одобренная для развёртывания»:
обнаружение версии и её одобрение не одно и то же. Первоначальный пользовательский
пример использует именно последнюю известную; нельзя незаметно подменить его одобренной.

Не смешивать состояния:

- равно эталону;
- ниже эталона;
- выше эталона;
- приложение не установлено при достоверном скане;
- неизвестно: скан неполный/устаревший, версия не распознана или эталон не получен.

Unknown не входит молча в «актуально» или «устарело». Для него отдельное условие/счётчик.
Новый эталон сам по себе не разрешает установку: по-прежнему действуют approval и policy.

## RAM: точные границы

Все требуемые выражения доступны:

| Выборка | Условие |
|---|---|
| 16 ГБ и более | RAM >= 16 ГБ |
| 8 ГБ и более | RAM >= 8 ГБ, включая ПК с 16+ |
| Менее 8 ГБ | RAM < 8 ГБ |
| От 8 до менее 16 ГБ | RAM >= 8 ГБ И RAM < 16 ГБ |

Для трёх непересекающихся групп использовать `<8`, `8–<16`, `>=16`.
Не путать их с пересекающимися `>=8` и `>=16`.
Сравнение выполнять по числовому значению/байтам, не по округлённой UI-строке.
Единицу ГБ/GiB и источник installed physical RAM явно определить в модели;
отсутствующие данные не считать нулём, usable/free RAM не подменяет installed RAM.

## Связь с развёртыванием

Любую коллекцию можно выбрать целью. До одобрения показать её текущий состав.
Созданный job закрепляет снимок DeviceId и package revision: последующий пересчёт
динамической коллекции не расширяет уже одобренное задание незаметно.
Расписание/политика при следующем разрешённом запуске может заново оценить выборку
по явно заданным правилам.

## Приёмка

1. Создать статическую группу, выбрать ПК, сохранить; restart не теряет состав.
2. Создать dynamic по RAM, увидеть preview, сохранить и открыть список.
3. Проверить границы 8/16 и Unknown, AND/OR, регистр имён и дубликаты ПО.
4. Связать software condition с ApplicationId и эталоном библиотеки.
5. Изменить библиотечный эталон на fixture: состав/счётчик меняются согласованно,
   никакая установка не запускается.
6. Новый scan переносит ПК между выборками, static membership не меняется.
7. Две консоли видят общую коллекцию; edit conflict не теряет изменения.
8. Для стартовой сети около 50 ПК не блокируется UI при preview/пересчёте;
   дальнейшую нагрузку на более крупных наборах измерять отдельно.
9. Создать вложенную папку/умную подгруппу, перенести, проверить запрет циклов.
10. Проверить union без повторов. Удаление группы не удаляет ПК; в макете есть отмена.

## Как попробовать макет

Открыть `mockups/sidebar.html` → «Группы» → `Приложения → Chrome`.
«Изменить» открывает правила и preview; «Создать подгруппу» — редактор нового элемента.
В «Проверить связь с библиотекой» поменять учебный эталон на `131.0.0.0`:
умные группы пересчитаются, ручная сохранит состав. Версии Chrome учебные,
не актуальные релизы Google. Reload сбрасывает данные, сохраняется только тема.
