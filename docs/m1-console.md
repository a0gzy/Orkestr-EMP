# Нативная консоль M1

Rust/egui 0.31.1, локальный SQLite backend, **без массового исполнения**.
Служба/HTTPS/DPAPI/сканирование/установка ПО отсутствуют. Закрытие M1-консоли
не является поддерживаемым режимом фоновой службы — это следующий этап M2.

## Запуск

После `cargo build --workspace --locked`:

```powershell
.\target\debug\orkestr-console.exe
# Или явно выбранная СУЩЕСТВУЮЩАЯ база Orkestr:
.\target\debug\orkestr-console.exe --database C:\MyData\orkestr.sqlite
```

Сборка в текущей среде требует GNU Rust и GCC; команды/helper: [m1-core.md](m1-core.md).
Не копировать toolchain/target соседних приложений. Без аргументов выберите
«Открыть базу» или «Создать пустую базу». Создание не перезаписывает существующий файл.
Данные не генерируются/не импортируются сами. База только локальная, не SMB.
При ошибке схема не подменяется пустой.

## Компьютеры и группы

- Боковая навигация A, исходный геометрический знак и Cobalt-палитра. Дерево папок
  и выборок; счётчик — уникальные DeviceId, не сумма детей. `?N` — Unknown условий.
- «+ Создать» / Ctrl+N: папка, ручная или умная группа. Название и родитель
  редактируются. «Создать подгруппу» у папки. Перенос — выбор нового родителя.
- В ручной группе отметьте ПК. В умной — поля/числовые операторы, И/ИЛИ и вложенные
  условия, software predicate на одной записи либо Unknown. RAM helpers `≥16`,
  `≥8`, `<8`, `8–<16` лишь заполняют свободно редактируемые правила.
- RAM сравнивается в точных installed bytes, GiB = 2³⁰. Неизвестное не равно нулю.
  Ссылки на library versions есть в модели; production discovery/matching — M4.
  Отсутствие библиотечного эталона даёт Unknown, не «актуально».
- Preview после debounce 180 мс работает на bounded worker, показывает количество,
  состав, ПО и Unknown до сохранения; «Сохранить» доступно после корректного preview.
  Preview не запускает сканирование. Static membership не меняется от нового скана.
- Циклы, родитель-выборка и конвертация/удаление непустой папки блокируются.
  Удаление требует подтверждения, не удаляет ПК/сканы. Stale revision не затирает
  другую правку; draft остаётся в редакторе, можно сохранить его новой группой.
- Список/дерево используют одну generation и время оценки. Локальный refresh раз
  в минуту или Ctrl+R не выполняет сетевых действий и не сбрасывает открытый draft.
- Поиск по ПК/ОС/домену и именам ПО не меняет сохранённую группу.

## Карточки

Нажмите ПК: обзор, оборудование/BIOS/RAM/CPU/диски, ПО, ОС/обновления,
пользователи/группы, процессы/службы, сеть/адаптеры/принтеры/ресурсы,
окружение/компоненты/автозагрузка/задачи. «Все данные» оставляет доступ к любым
дополнительным полям источника. Несобранный раздел не выдан за успешный пустой скан.
ScanId/UTC и warnings доступны. В M1 новых сканов нет.

«Пакеты»: версии, PackageId/RevisionId, описание/папка и определения шагов для review.
Нет кнопок установки/reboot/исполнения. Installer path не читается;
revision без проверенных artifact hashes не является доверенным пакетом.

## Импорт

1. Формат и локальная закрытая копия. Inventory — SQLite backup/VACUUM INTO, не
   копия живого WAL. Подтвердите владение копией.
2. Для Deploy при необходимости задайте стабильное «Происхождение» одного старого
   сервера: namespace PackageId, не эвристика по имени приложения.
3. Dry-run: SHA-256, исходная generation, количества, warnings/blocking errors,
   review-only records и rollback report. Источник не изменяется.
4. Подтвердите импорт; введите НОВЫЙ путь rollback backup или выберите в диалоге.
   Существующий backup не перезаписывается. Worker проверяет ticket/hash/generation,
   создаёт согласованный backup и применяет batch одной транзакцией.
5. ПК/пакеты видны в одной консоли. «Требует проверки» содержит выключенные
   schedules/target lists, историю без outputs и неподдержанные старые правила.
   Next/recurrence/was_enabled сохранены; unresolved targets не создают новые ПК.
   Отсюда нельзя запустить/активировать автоматику.

Смена source/формата/namespace сбрасывает dry-run. Повтор hash идемпотентен.
Ошибка не даёт частичный импорт. Backup восстанавливают в новый рабочий путь при
закрытых handles; автоматического restore поверх живой БД нет.

БД/backup/definitions приватны. Произвольные legacy commands и Environment могут
содержать чувствительные строки — это не безопасный public export. Config/token/DPAPI
и history outputs не переносятся. Parse/SQL ошибки не печатают raw source.

## Темы и клавиатура

Light/Dark/System и zoom 100/125/150/200%. Сохраняются только персональные настройки,
не секреты и не auto-open выбранной БД. Segoe UI/Consolas читаются из установленных
шрифтов Windows, не копируются в проект; есть eframe fallback. Значки векторные.
Ctrl+N — группа; Ctrl+F — поиск; Ctrl+R — refresh; Escape — отмена редактора;
F1 — встроенная справка. Стандартные egui focus/AccessKit.
Полная screen reader/High Contrast/физическая Windows DPI матрица не заявляется.

## Повторить безопасный smoke

```powershell
.\tools\smoke-console.ps1
```

Скрипт явно создаёт НОВУЮ папку в `test-results`, 50 **синтетических** ПК и две
legacy-копии. Hashes сверяются до/после; импортируются только эти копии, создаются
тестовые группы и выполняются native captures/повторное открытие. Настоящие данные
владельца и старые приложения не выбираются автоматически.
`tools/create-m1-fixtures.py --out <NEW-directory>` сам только пишет fixtures;
обычный запуск консоли его не вызывает.

Render smoke flags: `--capture <NEW.png>`, `--capture-view <overview|group|editor|device|packages|import|review|settings>`,
`--theme <light|dark|system>`, `--zoom <0.8..2>`. Они не меняют БД и не сохраняют
принудительную capture-тему в персональные настройки.

Результаты/ограничения: [m1-console-verification.md](m1-console-verification.md).
