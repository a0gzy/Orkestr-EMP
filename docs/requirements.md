# Требования и границы

## Принцип продукта

Одна карточка ПК связывает оборудование, установленное ПО, доступность,
профиль подключения и историю развёртываний. Одна карточка приложения связывает
источник версии, установочный пакет, обнаружение на ПК, одобрения и политики.

## Коллекции — не только строка поиска

Обязательная часть первой версии. Нужны сохранённые выборки, список компьютеров,
счётчик и видимые причины попадания: версии установленного ПО и сведения об оборудовании.
Примеры, поведение Unknown и связь с библиотекой — [collections.md](collections.md).
В HTML A добавлены группы, дерево папок, перенос и редактор на fixture. Это не
серверная реализация. Общий engine/редактор входят в M1, сравнение с реально
обновляющейся библиотекой завершается вместе с M4. Вложенность папок не равна
вложенности логических выражений: прототип поддерживает один уровень И/ИЛИ.
Сокращённая карточка ПК в HTML не отменяет F21.

## Нефункциональные требования

- TLS проверяется всегда. Никаких `SkipCACheck`, `TrustedHosts=*`, Basic по HTTP.
- База не публикуется по SMB; сервер единственный владелец, клиенты через API.
- UI не блокируется сканом/LDAP/скачиванием. Ограниченные worker pools и вывод.
- Нулевой статус «успех» без фактического результата, receipt или detection.
- Импорт и upgrade обратимы через backup; секреты не входят в обычный export.
- Стабильные UUID и UTC; Windows-имена без учёта регистра, IP не главный идентификатор.
- Численные SLO определяются после уточнения масштаба и benchmark; сейчас не обещаются.

## Вне первой версии

Постоянные агенты, Интернет-доступ к endpoint без VPN, P2P/branch relay,
MDM, Linux/macOS, облачный multi-tenant, обход NTLM/UAC/TLS политик,
проприетарная совместимость PDQ, универсальный rollback любого стороннего установщика,
визуальное выделение элемента на произвольном live-сайте через встроенный браузер.

Для HTML в V1: URL + CSS selector + предпросмотр извлечённого значения.
Страницы с JavaScript-only данными обозначаются как неподдерживаемые; API предпочтительнее.
Визуальный picker — отдельный будущий этап с изоляцией WebView.
